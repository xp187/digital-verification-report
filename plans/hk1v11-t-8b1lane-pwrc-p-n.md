# PWRC_P / PWRC_N 验证计划

## 验证目标

验证 `CHIP_SEL=1` 时，通过 CHPI 写入 `PWRC_P[1:0]`、`PWRC_N[1:0]` 后，C 时段的数字功率控制输出按配置变化，P/N 可以独立设置，且修改这两个字段不会改变 A/B 时段的控制码。

最终检查点使用数字顶层的实际端口：

```text
chip_tb_top.u_HK1V11.u_HK1V11_digital_top.PWRC_SOP_P[2:0]
chip_tb_top.u_HK1V11.u_HK1V11_digital_top.PWRC_SOP_N[2:0]
```

## 寄存器与预期编码

- `PWRC_P[1:0]`：`CHIP_SEL=1` 的 `0x0A[5:4]`，C 时段 P 路设置。
- `PWRC_N[1:0]`：`CHIP_SEL=1` 的 `0x0A[7:6]`，C 时段 N 路设置。
- 依据当前 RTL 的两位到三位编码关系制定固定期望表。运行时不从内部寄存器或实际输出反算期望。

| 写入配置 | 期望三位控制码 |
| :---: | :---: |
| `00` | `010` |
| `01` | `100` |
| `10` | `101` |
| `11` | `111` |

当前 RTL 在 `0x0A` 尚未写入时使用 `10` 作为 P/N 默认配置。正式检查须在该地址写入生效后开始。

## 固定配置

- 采用现有正常 8-bit、单 lane、12 ports、3840×16、8 帧传输，`CHIP_SEL=1`、`PORSD=1`。
- 设置 `TEST_PRTCT=0x72`，`CTRLF_CHECKSUM=0101`，关闭三帧校验保护等待。
- 设置 `VPS_EN=00`，避免消隐省电覆盖；主功能检查选择 `R_BKDU=0` 的正常输出周期。
- 固定 `PWRC_TA=01`、`PWRC_TB=01`、`PWRC_TSEL=0`，使 A/B/C 三段都可观察。该 case 检查各段控制码，不比较 A/B 的绝对持续时间。
- 固定 `PWRC_PA=00`、`PWRC_NA=00`，所以 A 段期望为 `P=010、N=010`。
- 固定 `PWRC_PB=01`、`PWRC_NB=01`，所以 B 段期望为 `P=100、N=100`。
- 保持既有正常输出时序，确保一个完整周期包含 A、B、C；不为此增加异常长的水平消隐。

## 八帧激励

| 帧 | `PWRC_P` | `PWRC_N` | C 段 P 路期望 | C 段 N 路期望 | 检查目的 |
| ---: | :---: | :---: | :---: | :---: | --- |
| 0 | `00` | `10` | `010` | `101` | P 最低编码、首次写入生效 |
| 1 | `01` | `10` | `100` | `101` | P 第二档 |
| 2 | `10` | `10` | `101` | `101` | P 第三档 |
| 3 | `11` | `10` | `111` | `101` | P 第四档 |
| 4 | `10` | `00` | `101` | `010` | N 最低编码、P 恢复基线 |
| 5 | `10` | `01` | `101` | `100` | N 第二档 |
| 6 | `10` | `10` | `101` | `101` | N 第三档 |
| 7 | `10` | `11` | `101` | `111` | N 第四档 |

`cfg_frame0.txt` 至 `cfg_frame7.txt` 对应上表；`cfg_frame8.txt` 重复最后一组配置，供基础发送流程使用。

帧 0～3 只遍历 P，N 应保持 `101`；帧 4～7 只遍历 N，P 应保持 `101`。全部帧的 A/B 段都应分别保持 `010/010`、`100/100`。C 段的 P/N 组合在这八帧中均不同于 A/B 组合，可识别错误的时段选择。

## 采样时机与精简 checker

1. 以每组 CTRL_F 配置实际生效为界推进预期配置；不能仅凭 `VS_O` 帧计数盲目切换期望，因为 CTRL_F 可能在视频帧边界前到达。
2. 配置生效后，选取第一个完整处于正常输出区的 A→B→C 周期；若更新发生在周期中间，使用下一个完整周期。
3. 使用 ANCTL 的时段信号定位：`PWRC_TIME=01` 为 A、`10` 为 B、`00` 为 C。该信号只定位采样阶段，预期控制码来自固定配置表。
4. 在 ANCTL.CLK（连接 DCLK）上升沿保存沿前时段，等待 1ns 后比较两个 digital_top 端口。输出寄存器在该沿使用沿前时段；此采样避开 NBA 和当前 RTL 触发器延迟。配置监视先收到 0x0A、再收到同组 0x1F，才允许开始完整周期检查。
5. A/B 段比较固定码，C 段比较当前组 P/N 的表内期望。失配报告配置组、时段、P/N 写入值、实际码和期望码。

实现仅需一个配置组索引、四档编码表及 A/B/C 三次采样比较，可用一个小 task 复用 P/N 端口比较；不引入通用 scoreboard、复杂状态机或逐位 checker。

## 通过条件

- 八组配置均至少完成一个有效 A→B→C 周期，每个阶段都采到 P/N 两个端口。
- A/B/C 控制码全部正确，P/N 独立配置正确，A/B 输出不受 P/N 修改影响。
- 不允许以跳过全部周期判通过。遇到配置更新、复位或 BKDU 打断的周期，重新选择完整周期；缺失阶段使用既有仿真总超时。
- 发送结束且最后一组配置检查完成后退出，不依赖第九个视频帧。

## 信号路径与依据

```text

          → LC_REG_MAPPING.PWRC_P/N
          → 两位译码、A/B/C选择、DCLK寄存
          → R_PWRCP_COP / R_PWRCN_COP
          → LINK_CONFIG_CTRL → LINK_LOGIC → LOGIC_CENTER.BUFFER_O
          → LOGIC_CENTER左侧COP输出
          → digital_top.PWRC_SOP_P / PWRC_SOP_N
```
