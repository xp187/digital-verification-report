t_8b1lane_REG_PASSTHRU 验证计划

1. 目的

验证 0x90~0x93 页（reg144~147）的数字直出寄存器：I2C 写入后，数字顶层输出正确跟随； 锁保护（LSI_PRTECT）未解锁时写入被屏蔽、输出保持默认值。

RTL 依据：cmodel/test/HV2A31/HDL/HK1V11_digital_top/seperated_code/LC_CPUWR.v（L532-581、L546）。 全部 7 个寄存器均为配置/支持信号：输出 = LSI_PRTECT ? 存储值 : 默认值，数字内无功能运算。 BCC_M 亦同——仅作为 BCC 解码器的手动模式半比特时长参数（boe_rx_bcc_decoder.v:266， 拼接 + mux 选择），不改变面板可见行为；与其余寄存器判据相同，仅观测点在数字内部。

2. 被测寄存器与观测点

寄存器 位 RTL 复位默认 观测点（LOGIC_CENTER 输出）
reg_fast_lock_rlpf 0x90[7:4] 4'b0110 reg_fast_lock_rlpf[3:0]
reg_fast_lock_icp 0x90[3:0] 4'b1000 reg_fast_lock_icp[3:0]
reg_fine_lock_rlpf 0x91[7:4] 4'b0011 reg_fine_lock_rlpf[3:0]
reg_fine_lock_icp 0x91[3:0] 4'b1100 reg_fine_lock_icp[3:0]
reg_lock_wd_sel 0x92[1:0] 2'b10 reg_lock_wd_sel[1:0]
FSEL 0x92[4:3] 2'b00 FSEL[1:0]（已连至 MACRO_TOP_1V11，数字侧观测 top 端口）
BCC_M 0x93[3:0] 4'b0010 BCC_M[3:0]；附加观测 bcc_ctrl 内部 boe_bcc_prescale_low_high_delta（M_BCC=1 时 = {2'b0,BCC_M}）

层次前缀：chip_tb_top.u_HK1V11.u_HK1V11_digital_top.u_LOGIC_CENTER.（bcc_ctrl 例化名实现时确认）。

3. 激励设计（无图像序列，纯寄存器级，参照 t_reg_i2c_unlock_rst）

  • 不跑帧、不训练：vseq 为空。参照 tests/t_reg_i2c_unlock_rst/t_reg_i2c_unlock_rst.sv 的成熟做法，全部流程放在 test 的 reset_phase 中（#100us 起步，复位释放后执行）。
  • I2C 接口（现成）： systemverilog `define I2C chip_tb_top.u_i2c_model_sim `I2C.i2c_write_single(.devid(7&#x27;h70), .address(8&#x27;h90), .data(wdata)); `I2C.i2c_read_single(.devid(7&#x27;h70), .address(8&#x27;h90), .rdata(rdata)); 0x90~0x92 不在 CHPI CTRL_F 0x00~0x3B 载荷内（见 t_8b1lane_DIRECT_OUT README）， I2C 是唯一写入路径。
  • 解锁两步（照抄先例）：devid 7&#x27;h62 写 F0=0x5A/F1=0xA5（I2C 使能），再 devid 7&#x27;h70 写 0x30=0x72（TEST_PRTCT）。
  • 写入值：各寄存器复位默认值取反——0x90←0x97、0x91←0xC3、0x92←0x19、0x93←0x0D； 可选回写默认值做第二组（0x90←0x68、0x91←0x3C、0x92←0x02、0x93←0x02）。
  • 流程：
  • 层次读 7 个输出 = 复位默认值
  • 未解锁写取反值 → 输出仍为默认值（锁定屏蔽）
  • 两步解锁，层次确认 LSI_PRTECT=1
  • 逐个写取反值，等待 ~10us 稳定窗，层次读输出比对；I2C 读回 = 写入值
  • （可选，借先例手段）force chip_tb_top.u_HK1V11.cr_done_lane = 0 后读输出， 确认 0x90~0x93 在失锁域的行为（回默认或保持）与 RTL 一致，随后 release

4. 判据（全部零 golden RTL，只查跟随关系）

  1. 默认值判据：起始 7 个输出 = 复位默认值。期望字节已按 HK1V11_Register_20251021 spec 定案（与 RTL 全部一致）：0x90=8'h68、0x91=8'h3C、 0x92=8'h02、0x93=8'h02。此前据旧截图记录的"三处默认值分歧"系版本对照错误，撤销。
  2. 锁定屏蔽判据：未解锁写取反值后，输出仍为默认值。
  3. 跟随判据（主判据）：解锁后写取反值，稳定窗内输出 = 写入值；I2C 读回一致。
  4. BCC_M 附加观测：顶层 BCC_M[3:0] 同判据 3；若配置下 M_BCC=1，附加检查 boe_bcc_prescale_low_high_delta = {2&#x27;b0, BCC_M}。M_BCC 模式切换归 BCC 专项 case。
  5. cr_done 失锁判据（可选）：force cr_done_lane=0 后 0x90~0x93 输出的行为 （回默认/保持）符合 RTL 复位域归属。

5. 风险与回退

  • N_RST_NLOCK 域风险（已被先例大幅降低）：t_reg_i2c_unlock_rst 已在 reset_phase 内不跑帧完成全地址段 I2C 读写，写路径有效性有保证。残余风险仅剩 0x90~0x93 输出 端口在本环境层次下是否可见（编译期即暴露）。
  • 回退：若判据 2/3 同时失败，改在 force cr_done_lane=1（模拟已锁定）后重复流程。

6. 非目标

  • 不验模拟端真实行为（OSC 频率、CDR 带宽变化）——只验数字透传
  • 不验 0x50/0x51 的 regr_* 回读监控寄存器（它们是状态回读，无写路径）
  • 不跑图像帧，不验 CHPI/图像功能
  • 不覆盖 VU440_FPGA 分支（该分支下 FSEL 悬空，属 FPGA 适配问题）

7. 完成条件

  • 判据 1~3 全部通过，判据 4 顶层跟随通过，零 UVM_ERROR
  • 每个寄存器 ≥1 组取反值采样（可选回写默认值则 ≥2 组）

8. 待确认项

  1. bcc_ctrl 在 LINK_PANEL_CTRL 内的例化名，及 M_BCC 是否为 1（判据 4 附加观测用）
  2. 0x92 bit[2] spec 名为 reg_pbs_fit，数字 RTL 无此信号（未实现或不归数字）—— 本 case 该位保持 0 不覆盖，仅记录
