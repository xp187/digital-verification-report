# khead_20b_sel 验证计划

## 1. 验证目标

验证新增寄存器字段 `khead_20b_sel[4:0]` 配置为 `5'b10101` 后，设计实际采用 20-bit K-head 模式，并在连续 8 帧中持续生效。像素、SIM_OUT、K-head 解码内容等数据正确性由环境已有 checker 检查；本 case 的专用 checker 只确认寄存器对应的有效模式选择信号。

## 2. 规格与配置

- 规格来源：`E:\projects\HK1V11\HK1V11_spec\05.Register\HK1V11_Register_20261102.xlsm`
- 寄存器地址：`0x33`
- 字段位置：`[6:2] khead_20b_sel[4:0]`
- 规格编码：`5'b10101` 选择 20-bit 模式；其他编码选择 40-bit 模式（默认）。
- 本 case 只使用 `5'b10101`，不遍历其他字段编码、不切换模式。测试配置在 `build_phase` 中设置一次；标准 420b 序列会在每帧 CTRL_F 中携带相同的固定值。
- 如果寄存器其他位 `[7]`、`[1]`、`[0]` 保持 0，打包后的整字节值为 `8'h54`。实际配置应通过项目的正常寄存器写入流程只更新 `[6:2]`，保留相邻字段的既有配置；不能因写整字节而意外修改这些位。
- CHIP_SEL 沿用该环境现有 case 的固定基线配置，8 帧中不切换 CHIP_SEL。

## 3. 用例流程

1. 按环境既有流程完成复位和基础初始化，并设置固定 CHIP_SEL。
2. 在第 0 帧开始前，通过正常寄存器配置路径将 `0x33[6:2]` 设为 `5'b10101`。该字段在整个用例中保持固定，不做模式切换；`cfg_frame0.txt` 至 `cfg_frame8.txt` 均携带相同值，以匹配环境每帧发送 CTRL_F 配置、并覆盖末帧后续配置行的流程。
3. 等待项目既有的配置生效/提交时序完成；不使用 force，也不通过层级赋值绕过寄存器路径。
4. 按原有正常帧间隔连续运行 8 个完整帧，编号为 frame 0 至 frame 7。保持环境默认的帧节奏，不压缩帧间隔，不额外插入模式切换或寄存器写操作。
5. 每帧在 K-head 模式选择已稳定、且该帧首次处理 K-head 的有效观察点采样一次有效模式选择信号，并记录帧号、期望模式和实际模式。
6. 由环境现有 checker 继续检查输入/输出数据；本 case 的 checker 不重复检查像素值、SIM_OUT 或解码数据。

## 4. 专用 checker 检查点

### 观察对象

观察 RTL 映射后的 `chip_tb_top.u_HK1V11.u_HK1V11_digital_top.u_LOGIC_CENTER.LINK_LOGIC.LINK_CONFIG_CTRL.LC_REG_MAPPING.khead_20b_sel[4:0]`。规格中 `5'b10101` 表示 20-bit K-head 模式，因此每帧首条活动行采样时该映射字段应为 `5'b10101`。

### 每帧期望

| 帧号 | 寄存器字段 | 期望有效模式 | 检查时机 |
|---:|---|---|---|
| 0 | `5'b10101` | 20-bit K-head | 配置生效后，本帧首次处理 K-head 时 |
| 1 | `5'b10101` | 20-bit K-head | 本帧首次处理 K-head 时 |
| 2 | `5'b10101` | 20-bit K-head | 本帧首次处理 K-head 时 |
| 3 | `5'b10101` | 20-bit K-head | 本帧首次处理 K-head 时 |
| 4 | `5'b10101` | 20-bit K-head | 本帧首次处理 K-head 时 |
| 5 | `5'b10101` | 20-bit K-head | 本帧首次处理 K-head 时 |
| 6 | `5'b10101` | 20-bit K-head | 本帧首次处理 K-head 时 |
| 7 | `5'b10101` | 20-bit K-head | 本帧首次处理 K-head 时 |

Checker 直接比较映射后的字段值；字段为 X/Z 或任一帧不是 `5'b10101` 时，报告带帧号的错误。像素、SIM_OUT 和解码数据继续交由环境 checker 检查。

### Checker 不负责的项目

- 不比较任何像素、SIM_OUT、输出字节或 K-head 解码数据。
- 不重复检查寄存器读回正确性；寄存器访问和数据正确性由环境已有机制负责。
- 不检查 `5'b10101` 以外的字段编码，不检查复位值，也不遍历 CHIP_SEL。
- 不改写环境 checker 的阈值、使能或判定逻辑。

## 5. 通过与失败判据

**PASS：** 字段在 frame 0 前按正常路径配置一次；8 个完整帧均到达有效检查点；每帧观察到的有效选择均为 20-bit；本 checker 无错误，环境既有 checker 也无错误。

**FAIL：** 配置后任一帧的有效选择不是 20-bit、控制信号未知、帧内没有可用的 K-head 观察点，或用例未能按正常时序完成 8 帧。日志应包含 case 名、帧号、字段配置值及实际有效模式，便于定位。

## 6. 实施约定

- case 设置 `env_cfg.khead_20b_sel=5'b10101`，通过环境正常 CTRL_F 配置路径驱动 RTL，不使用 force 或层级写寄存器。
- 序列在每帧 row 0 的 K-head 输入前检查映射字段；完整结束后确认恰好检查 8 帧。
- 安装脚本不生成或复制 PPM 文件；运行时沿用仿真环境提供的标准输入图像。
